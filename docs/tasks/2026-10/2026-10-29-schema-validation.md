# Schemas written in cola, and `colap check --schema`

## Objective

A cola file can declare the shape another cola file must have: entity kinds, fields,
types, required and optional fields, closed token sets, references to other entities,
and whether unknown keys are allowed. `colap check --schema S.md FILE...` enforces it,
and the code generator can generate from the schema rather than inferring types from
example values.

## Context

- **Unknown keys and wrong types are silently accepted.** Downstream code generated by
  colap simply ignores them; chaiss recorded this as an adoption pain.
- **Generated types are guessed from example literals.** A field that happens to hold
  `1` in the sample becomes `i64` forever.
- **Downstream projects write their own checks.** One knowledge repository's registry
  declares kinds, predicates and qualifiers with types in cola. Its linter then has to
  re-implement generic checks that belong in colap: required fields, allowed qualifiers,
  closed vocabularies, reference resolution. A colap-level schema would let that registry
  be checked by colap itself.

## Deliverables

1. **A design record** for the schema dialect, itself valid cola. A sketch:

        schema:
            entity plural entities:
                claim:
                    collection: true, unknown_fields: "error"
                    field plural fields:
                        subject: type: "reference", required: true;
                        basis: type: "symbol", one_of: "mirrored parsed derived inferred";
                        value: type: "number";
                    ;
                ;
            ;
        ;

2. **A validator** reporting through the `colap check` diagnostics channel
   (`2026-10-29-colap-check-and-diagnostics.md`):
   - missing required fields;
   - unknown fields;
   - type mismatches;
   - values outside `one_of`;
   - dangling references.
3. **Generator support.** The generator takes `--schema`, so Rust types come from
   declarations: optional fields become `Option`, closed sets become Rust enums.
4. **Tests,** including a schema validating a small literate file and failing cleanly on
   each kind of violation.

## Explicitly out of scope

- Cross-file reference resolution across a whole repository. colap validates one model,
  possibly merged from several files given on the command line; repository-wide indexing
  stays with downstream tools.
