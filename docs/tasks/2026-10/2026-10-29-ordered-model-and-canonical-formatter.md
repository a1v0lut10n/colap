# Preserve source order and add a canonical formatter (`colap fmt`)

## Objective

The model preserves the source order of fields and entries. A formatter rewrites cola
blocks into one canonical layout, byte-for-byte deterministically, and leaves prose
untouched. A file can then be round-tripped and regenerated with stable diffs.

## Context

- **Downstream tools need byte-deterministic files.** A downstream knowledge repository's derived views and headers are
  regenerated by tools, and any hand edit counts as drift. That only works if writing
  cola is deterministic.
- **Writing cola is not deterministic today:**
  - entity fields live in a `HashMap`, so iteration order varies between runs;
  - generated plural wrappers are `HashMap<String, T>` and lose entry order;
  - nothing can write cola back out.
- **Order carries meaning in literate and append-only files.** Batches are read in order,
  and diffs must show appended entries at the end.

## Deliverables

1. **Ordered collections.** Replace `HashMap` with an insertion-ordered map (for example
   `indexmap`) for entity fields and children in `ConfigModel`. Do the same in generated
   plural wrappers, or provide ordered iteration beside keyed lookup.
2. **A writer.** `ConfigModel::to_cola()` emits canonical cola:
   - fixed indentation;
   - one field per line beyond a width threshold;
   - no trailing commas;
   - `;` placement fixed;
   - strings re-quoted consistently.
3. **`colap fmt FILE...`** rewrites only the bodies of cola fences, in place. `--check`
   exits 1 if a file is not canonical.
4. **A round-trip property test:** parse, then format, then parse again gives an equal
   model, and formatting twice equals formatting once.

## Explicitly out of scope

- Reflowing markdown prose.
